## API HTTP

Todos os endpoints levantados, por área. A coluna **Permissão** é a que a view
exige de fato — no BWA Tech a autorização é decidida por `has_perm` sobre o
catálogo de permissões, nunca por comparação de cargo.

### Roteamento raiz e rotas públicas

| Método | Rota | View | Permissão | O que faz |
|---|---|---|---|---|
| `GET` | `/api/` | config.views.api_root | PÚBLICO — view Django pura (JsonResponse), sem decorator de autenticação | Raiz da API: JSON com version 1.0.0 e um dicionário de endpoints. É o alvo do HEALTHCHECK do Dockerfile (curl -fsS http://localhost:8000/api/). |
| `ALL` | `/admin/` | django.contrib.admin.site.urls | is_staff (padrão do admin) | Django admin. |
| `POST` | `/api/users/register/` | apps.accounts.views.RegisterView | pública; throttle escopo 'register' 5/min | Cadastro. Registrada AQUI, antes dos include(), para não ser capturada pelo router do accounts (que casaria users/<pk>/). |
| `POST` | `/api/users/login/` | apps.accounts.views.LoginView | pública; throttle escopo 'login' 10/min | Login. Mesmo motivo da rota acima para vir antes do include. |
| `GET` | `/api/portal/formularios-access/` | apps.formularios.portal_views.PortalFormulariosJWTView | — | Devolve o JWT (`access`) do portal externo para o SPA consumir a API de formulários direto. |
| `ALL` | `/api/portal-formularios/<path:path>` | apps.formularios.portal_proxy_views.PortalFormulariosProxyView | — | Proxy HTTP para {PORTAL_BASE_URL}/api/formularios/* — mesma origem no browser, evita CORS na LAN. Valida a base contra SSRF e devolve 503 se PORTAL_BASE_URL não estiver configurada. |
| `GET/POST` | `/api/feedback/<str:token>/` | apps.feedbacks.views.FeedbackPublicoView | AllowAny; throttle_classes SUBSTITUI a lista default: FeedbackIPThrottle + FeedbackTokenThrottle | Feedback anônimo. Token no PATH e não na query string (query string cai no access log e no header Referer enviado a terceiros). Registrada antes dos include() porque o urlconf termina em catch-all serve_spa — registrada depois, devolveria index.html com HTTP 200 onde o front espera JSON. |
| `-` | `/api/ → include('apps.accounts.urls')` | apps.accounts.urls | — | Router: users/, cargos/, setores/. Mais users/register/, users/login/, users/logout/, users/logout-all/, users/recover-account/ (register e login duplicam as registradas no urls.py raiz). |
| `-` | `/api/ → include('apps.projects.urls')` | apps.projects.urls | — | Router: sprints/, projects/, cards/, notes/, card-pins/, events/, card-logs/, notifications/, weekly-priorities/, weekly-priority-config/, card-date-change-requests/, card-reopen-requests/, kanban-stages/, score-criterios/, card-scores/, card-anexos/. Fora do router: notifications/preferences/. |
| `-` | `/api/ → include('apps.suggestions.urls')` | apps.suggestions.urls | — | Router: suggestions/. |
| `-` | `/api/ → include('apps.geekday.urls')` | apps.geekday.urls | — | Router: geekday-draws/, geekday-grupos/. |
| `-` | `/api/ → include('apps.reports.urls')` | apps.reports.urls | — | Router: reports/. |
| `-` | `/api/ → include('apps.feedbacks.urls')` | apps.feedbacks.urls | — | Router: feedbacks/pedidos/. Fora do router (são DOWNLOAD, não recurso REST): feedbacks/exportar/ e feedbacks/exportar/previa/. |
| `-` | `/api/formularios/ → include('apps.formularios.urls')` | apps.formularios.urls | — | ÚNICO include com prefixo próprio. Router: suporte/, suporte-timeline/, suporte-resolucao/. |
| `GET` | `/media/<path:path>` | config.views.serve_media | Prefixos abertos: profiles/, card_anexos/, suporte_resolucao/. Prefixo reports/ SEMPRE 404, nem para autenticado. Todo o resto exige sessão Django ou token da API. | Serve mídia em dev E prod, com cache imutável de 1 ano e revalidação 304 (ETag/If-Modified-Since). Dispensa o django.conf.urls.static.static() do modo DEBUG. |
| `GET` | `^(?P<path>.*)$ (catch-all)` | config.views.serve_spa | PÚBLICO — sem autenticação nenhuma | Serve o build do Vite (frontend/dist): arquivo estático se existir dentro do build, senão index.html para o React Router resolver. Se FRONTEND_BUILD_DIR não existir, devolve JSON 404 pedindo `npm run build`. |

### Contas, autenticação e catálogos

| Método | Rota | View | Permissão | O que faz |
|---|---|---|---|---|
| `POST` | `/api/users/register/` | RegisterView (accounts/views.py) — registrada TAMBÉM em config/urls.py antes do include | AllowAny, authentication_classes=[], csrf_exempt, throttle 'register' = 5/min | Cadastro público. Exige first_name, username, email @bwa.global e senha forte; foto opcional. Nasce com role='visitante' (zero permissões) e vinculado ao setor padrão do sistema. Devolve user, token, expires_at e recovery_code (única vez que o código aparece no cadastro). |
| `POST` | `/api/users/login/` | LoginView (accounts/views.py) — registrada TAMBÉM em config/urls.py antes do include | AllowAny, authentication_classes=[], csrf_exempt, throttle 'login' = 10/min | Login por e-mail + senha. Rotaciona o token (deleta os existentes e cria um novo), devolvendo token com 24h cheias e `expires_at` ISO. |
| `POST` | `/api/users/logout/` | LogoutView | IsAuthenticated | Remove apenas o token usado nesta requisição (request.auth) e chama logout(request). |
| `POST` | `/api/users/logout-all/` | LogoutAllView | IsAuthenticated | Remove TODOS os tokens do usuário — encerra a sessão em todos os dispositivos. |
| `POST` | `/api/users/recover-account/` | RecoverAccountView | AllowAny, authentication_classes=[], csrf_exempt, throttle 'recovery' = 5/hora | Recupera acesso via recovery_code: redefine a senha, ROTACIONA o código (o antigo deixa de valer) e apaga todos os tokens do usuário. Mensagem de erro unificada para evitar enumeration. |
| `GET` | `/api/users/` | UserViewSet.list | IsAuthenticated | Lista usuários. Exclui role='admin'; aplica scope_users (só quem compartilha setor, quando SETOR_SCOPING_ENABLED); filtros ?role= e ?participa_do_trabalho=1\|true (só quem tem view_content e is_active). |
| `POST` | `/api/users/` | UserViewSet.create | CanManageUsers (accounts.manage_users) | Cria usuário pela gestão. O serializer também grava o vínculo M2M UserSetor (sem ele o usuário abriria a plataforma vazia com o escopo ligado). |
| `GET` | `/api/users/{id}/` | UserViewSet.retrieve | IsAuthenticated | Detalhe do usuário. O queryset permite o próprio usuário mesmo sendo admin (Q(pk=self) \| ~Q(role='admin')). |
| `PUT / PATCH` | `/api/users/{id}/` | UserViewSet.update | IsAuthenticated + checagens internas (has_perm('accounts.manage_users') ou ser o próprio) + validate_role/validate_setor no serializer | Edita usuário: o próprio (perfil) ou quem tem manage_users. Trocar o PRÓPRIO cargo é vedado a TODO MUNDO, inclusive a quem tem manage_users. `is_active` é read_only aqui. Se role ou setor mudarem, emite permissions_changed. |
| `DELETE` | `/api/users/{id}/` | UserViewSet.destroy | IsAuthenticated (irrelevante: responde 405 antes) | SEMPRE 405. Contas não são excluídas — a mensagem manda usar /users/{id}/set-active/ com is_active=false, porque todo o histórico (sprints, projetos, cards, anexos, logs) aponta para o usuário. |
| `GET` | `/api/users/all/` | UserViewSet.all_users | CanManageUsers | Lista TODOS os usuários, inclusive admins, para a tela de Gerenciamento de Usuários. Suporta ?search= em username/first_name/last_name/email. Queryset próprio — NÃO passa por scope_users. |
| `GET` | `/api/users/permissions-catalog/` | UserViewSet.permissions_catalog | CanViewPermissionCatalog (manage_user_permissions OU manage_users OU manage_cargos) | Catálogo completo das 29 permissões: [{codename, name, area}] — popula os switches das telas de gestão de usuários e de cargos. |
| `GET` | `/api/users/me/` | UserViewSet.me | IsAuthenticated | Usuário autenticado serializado (é a fonte de verdade que o cliente refaz ao receber o evento permissions_changed). |
| `POST` | `/api/users/change-password/` | UserViewSet.change_password | IsAuthenticated | Troca a própria senha exigindo a senha atual. Body: current_password, new_password (min_length=8). |
| `GET` | `/api/users/recovery-code/` | UserViewSet.recovery_code | IsAuthenticated | Devolve o recovery_code atual do usuário autenticado. |
| `POST` | `/api/users/recovery-code/` | UserViewSet.recovery_code | IsAuthenticated | Rotaciona o recovery_code: gera um novo (único no DB) e invalida o anterior. O código não expira por tempo. |
| `POST` | `/api/users/profile-picture/` | UserViewSet.profile_picture | IsAuthenticated | Atualiza a foto do próprio usuário (multipart, campo `profile_picture`). Valida tamanho (5 MB), MIME, magic bytes e integridade via Pillow; redimensiona para 512px, re-encoda como JPEG e renomeia com uuid. |
| `POST` | `/api/users/{id}/set-permissions/` | UserViewSet.set_permissions | CanManageUserPermissions (accounts.manage_user_permissions) + travas de alvo (nunca a si mesmo; admin só por admin) | Substitui o conjunto de permissões personalizadas do alvo pela lista `codenames`. Valida contra o catálogo e aplica a trava anti-escalonamento (403 se conceder o que não possui). Emite permissions_changed. |
| `POST` | `/api/users/{id}/set-active/` | UserViewSet.set_active | CanManageUsers + travas de alvo | Ativa/desativa o alvo. Body: {is_active: bool}. Ao desativar (transação única): revoga todos os tokens, solta os cards ABERTOS (desatribuir_cards_de_usuario_desativado) e emite account_deactivated no on_commit. Ao reativar, emite permissions_changed. |
| `POST` | `/api/users/{id}/reset-password/` | UserViewSet.reset_password | CanManageUsers + travas de alvo | Redefine a senha do alvo sem exigir a senha antiga. Body {new_password} ou vazio para sortear uma forte (a senha sorteada volta em `senha_gerada` e em nenhum outro lugar). Revoga todos os tokens do alvo e emite account_deactivated. 403 explícito se pk == request.user.pk. |
| `DELETE` | `/api/users/{id}/setores/{codename}/` | UserViewSet.remover_setor | CanManageUsers + travas de alvo | Desvincula o usuário de um setor (a única remoção de UserSetor — todas as outras escritas são get_or_create). Se era o primário, o vínculo mais antigo assume; aplica a regra do balde de não classificados; grava BulkOperationAudit e emite permissions_changed. 404 se não houver vínculo. |
| `POST` | `/api/users/bulk-assign-cargo/` | UserViewSet.bulk_assign_cargo | CanManageUsers (+ _bulk_targets replica as travas de alvo) | Atribui um cargo a vários usuários. Body: {cargo_codename, user_ids[], apply_template?}. `apply_template` COPIA permissoes_padrao para user_permissions com `add` (nunca `set`). Só admin atribui o cargo 'admin'. Superusers são ignorados. Grava BulkOperationAudit e emite permissions_changed. |
| `POST` | `/api/users/bulk-assign-setor/` | UserViewSet.bulk_assign_setor | CanManageUsers (+ travas via _bulk_targets) | Define o setor primário de vários usuários. Body: {setor_codename ('' para limpar), user_ids[]}. Sincroniza CharField E vínculo M2M. Grava BulkOperationAudit e emite permissions_changed. |
| `POST` | `/api/users/bulk-set-permissions/` | UserViewSet.bulk_set_permissions | CanManageUserPermissions (+ travas via _bulk_targets) | Aplica permissões a vários usuários. Body: {codenames[], mode: 'set'\|'add'\|'remove', user_ids[]}. Mesma trava anti-escalonamento do set-permissions individual. Grava BulkOperationAudit e emite permissions_changed. |
| `GET` | `/api/cargos/` | CargoViewSet.list | IsAuthenticated | Lista os cargos do catálogo (id, codename, nome, is_system, cor, label_curto, descricao, permissoes_padrao, user_count). |
| `POST` | `/api/cargos/` | CargoViewSet.create | CanManageCargos (accounts.manage_cargos) | Cria um cargo. `codename` é derivado do nome (slugify + sufixo em colisão) e `is_system` é forçado a False. Aplica a trava anti-escalonamento sobre permissoes_padrao. |
| `GET` | `/api/cargos/{id}/` | CargoViewSet.retrieve | IsAuthenticated | Detalhe de um cargo. |
| `PATCH` | `/api/cargos/{id}/` | CargoViewSet.partial_update | CanManageCargos | Edita nome/cor/label_curto/descricao/permissoes_padrao (codename e is_system são read_only). Só o DELTA que ENTRA em permissoes_padrao é verificado contra o que o editor possui. Emite permissions_changed para TODOS os portadores do cargo. PUT não existe (http_method_names). |
| `DELETE` | `/api/cargos/{id}/` | CargoViewSet.destroy | CanManageCargos | Exclui um cargo. 403 se is_system=True; 409 com `usuarios_vinculados` se houver usuários com esse role. Limpa o cache de choices. |
| `GET` | `/api/setores/` | SetorViewSet.list | IsAuthenticated | Lista os setores do catálogo (mesmos campos de Cargo, sem permissoes_padrao; `user_count` conta pelo CharField `User.setor`). |
| `POST` | `/api/setores/` | SetorViewSet.create | CanManageSetores (accounts.manage_setores) | Cria um setor (codename derivado do nome, is_system forçado a False). |
| `GET` | `/api/setores/{id}/` | SetorViewSet.retrieve | IsAuthenticated | Detalhe de um setor. |
| `PATCH` | `/api/setores/{id}/` | SetorViewSet.partial_update | CanManageSetores | Edita nome/cor/label_curto/descricao. PUT não existe. |
| `DELETE` | `/api/setores/{id}/` | SetorViewSet.destroy | CanManageSetores | Exclui um setor. 403 se is_system; 409 se houver usuários vinculados (CharField OU M2M) ou dados vinculados (sprints/projetos/cards/chamados) — a checagem existe porque as FKs são PROTECT e o delete estouraria 500. |
| `POST` | `/api/setores/{id}/atribuir-dados/` | SetorViewSet.atribuir_dados | CanManageSetores | Classifica conteúdo neste setor. Body: {sprint_ids?, project_ids?, todos?}. Propaga em árvore (sprint → projetos → cards; projeto → cards). NÃO aceita card_ids (Card.setor é espelho do projeto). `todos=true` move o que ainda está no setor padrão. Recusa 409 se a mudança deixar duas sprints em andamento no mesmo setor. Sprints/projetos/cards do fluxo sistêmico (sprint__is_system) ficam FORA de qualquer movimentação. Remove compartilhamentos que viraram redundantes. |

### Sprints, projetos, cards e satélites

| `GET` | `/api/projects/{id}/` | ProjectViewSet.retrieve | IsAuthenticated + PodeVerConteudo | Detalhe. Ações de detalhe NÃO filtram por `arquivado` — senão a URL direta de um projeto arquivado daria 404 e não haveria como desarquivá-lo. |

| Peça | Tipo | O que faz | Arquivo |
|---|---|---|---|
| `WebSocket /ws/notifications/ — NotificationConsumer` | channels consumer | Autentica por Token (query string ?token= ou header 'Authorization: Token <k>'), entra no grupo user_<id> e aceita. | `WebSocket /ws/sprints/<sprint_id>/kanban/ — SprintKanbanConsumer` | channels consumer | Grupo sprint_<sprint_id>_kanban, compartilhado por todos os clientes vendo aquela sprint ou qualquer projeto dela. | `WebSocket /ws/suporte/ — SuporteKanbanConsumer` | channels consumer | Resolve no connect em QUAIS grupos entrar e congela a lista pela sessão: flag de escopo desligada → grupo global 'suporte_kanban'; sem 'accounts.view_all_tickets' → só o grupo de posse do próprio e-mail; com bypass de escopo (superuser / view_cross_setor) → 'suporte_kanban_todos'; demais privilegiados → 'suporte_kanban_sem_setor' mais um grupo por setor seu. | `broadcast_solicitacoes_changed` | publicação no channel layer via notify_users | Manda {'type':'solicitacoes_changed'} — literalmente sem payload — para quem tem 'view_content' recortado pelo setor que alcança o card, mais os sempre_ids (o solicitante).
